== Overview

`check-script` is a Dart library (`lib/`) exposed through a CLI
(`bin/check_script.dart`) and a Flutter interface (`gui/`). It orchestrates
analyzers for shell and Python 3 scripts (external tools and built-in
rules),
normalizes their results into *findings* (`Finding`) classified by category and
severity, deduplicates them, applies directives, contexts and configuration,
computes the scores and produces the reports. It can also fix the
safe defects and compare an analysis against a baseline.

=== Principles

* *Use existing tools* (ShellCheck, shfmt, bashate,
  checkbashisms, gitleaks, trufflehog, `bash -n`) rather than rewrite them;
  the built-in rules cover what they do not handle and provide a
  minimal analysis without them.
* *Graceful degradation*: a missing tool is reported, never blocking;
  without shfmt, the structural rules fall back to a heuristic lexer.
* *Library first*: `lib/` never writes to the console; the CLI and
  the interface are only facades.
* *Testability*: command execution goes through `CommandRunner`
  (replaced by a fake in the tests); parsers are pure functions tested on
  recorded *real* outputs; a corpus freezes the behavior on real scripts.
* *No secret leaks*: secrets are never copied into reports, trufflehog is
  run without network verification.

== Analysis flow

----
file ──► ScriptInfo.fromContent (shebang or .py extension → Dialect, CRLF, lines)
              │
              ▼
Engine.analyze ── for each enabled Analyzer of the script's language (analyzersFor),
              │   in priority order:
              │     shell  : syntax → shellcheck → gitleaks → trufflehog → checkbashisms
              │              → builtin (shfmt tree if available) → shfmt → bashate
              │     python : syntax → bandit → ruff → semgrep → mypy → pyright → pylint
              │              → vermin → radon → gitleaks → trufflehog → builtin (ast)
              │     tools run in parallel (Future.wait), results stored in
              │     priority order; Engine(parallel: false) for strict order
              │     onProgress(AnalysisProgress); CancelToken checked for each tool
              │   analyzeFiles(paths, jobs): several scripts at once (default
              │     Engine.defaultJobs = processors / 4, between 1 and 4), order preserved
              ▼
deduplicate   ── keeps the first of each group of duplicates
Suppressions  ── # check-script disable… directives (counted in `suppressed`)
enrich        ── documentation links, generic hints for external tools
escalate      ── severities raised according to contexts (root, cron, systemd)
applyConfig   ── rules.disabled, rules.overrides
fingerprintAll── stable fingerprints (baseline, SARIF, Code Quality)
sortFindings  ── category, severity, line
scoreCategory × 5, globalScore
              ▼
ScriptReport ──► Baseline.compare (if baseline) ──► render(format)
----

== Model

`Finding`:: `tool`, `ruleId`, `category`, `severity`, `line` (0 = file),
`column`, `message`, `snippet`, `equivalents` (codes of other tools
designating the same defect), `hint` (advice), `url` (documentation),
`fingerprint`, `endLine` (end of the reported multi-line statement, used for
deduplication: line overlap, extent ≤ `maxDuplicateSpan`),
`edits` (concrete fix: 1-based `TextEdit`, exclusive end;
coming from ShellCheck's `fix` or from `attachFixes` for the
built-in fixes). `Finding.fromJson` reads back `toJson`.
`fixPreview` derives the before / after lines from it; `exampleFor`
(`rules/examples.dart`) gives the generic example of a rule.

`ToolRun`:: `ok`, `missing`, `skipped`, `failed`, `disabled`; version;
number of findings; `detail` (`ast` / `lexer` for built-in rules).

`ScriptReport`:: script, tools, findings, 5 `CategoryScore`, global score,
grade, date, `suppressed`, `profile`, `contexts`, `comparison`.

== Analyzers

[source,dart]
----
abstract class Analyzer {
  String get name;                                   // configuration key
  ToolLanguage get language;                         // shell (default), python or any
  Future<AnalyzerResult> analyze(AnalysisContext ctx);
  Future<String?> version(CommandRunner runner, CheckConfig config); // null = absent, '?' = unreadable
}
----

`CommandRunner.run(exe, args, {stdin, cancel})` returns `null` if
the executable cannot be found. `ProcessCommandRunner` forces `LC_ALL=C`, writes
`stdin` (used by `shfmt --to-json`, `bash -n`, the formatting of `--fix`)
and kills the process when the `CancelToken` is triggered. Analyzers
go through `ctx.run(...)`, which forwards the token.

=== ShellCheck code classification

`shellcheckMap` explicitly classifies the significant codes; otherwise
`classifyShellcheck` applies: SC3xxx → Portability (Medium/Low), SC1xxx
`error` → Robustness/High, `style` → Maintainability/Low, otherwise Robustness
according to the level. Bashisms that *break under dash* (SC2112/2113
`function`, SC3010 `[[`, SC3011 `<<<`, SC3020 `&>`, SC3030/3054 arrays,
SC3005/3006 `((`, SC3018, SC3001) are High — a decision resulting from
calibration.

=== Deduplication

Two findings are duplicates if one of the `equivalents` of one matches the
`ruleId` of the other (exact or `*` prefix) and they concern the same
line — or one of them is a "file" finding (line 0) or a `SYNTAX` error. Same
tool: same line and (same rule or equivalent). The first one encountered is
kept; the order of `defaultAnalyzers()` sets the priority.

=== Python equivalences

Ruff `Snnn` = Bandit `Bnnn` (same numbers); Ruff `PLxnnnn` = Pylint
`xnnnn`; `_ruffToPylint` table for the others (`E722` = `W0702`, `B006` =
`W0102`…); Semgrep is equivalent to the Bandit and Ruff security codes on the same
line; mypy to Pyright diagnostics (`report*`); *version* errors
(`match` in 3.9) from Ruff and Pyright are classified as Portability and are
equivalent to `VERMIN`. Bandit B105–B107 messages and Semgrep "secret" messages
are redacted, and their lines masked (`_revealsSecret`).

== Built-in rules

=== Catalog

`rules/catalog.dart` describes each rule: identifier, category, severity,
bilingual title and *fix hint* (`Tr`), activation contexts.
Detection is separate (`builtin_rules.dart`); `add(id, line, …)` creates
the `Finding` from the catalog and ignores rules whose context
is not declared.

=== Syntax tree (shfmt) and lexer fallback

`AstFacts` (`analyzers/ast.dart`) walks the JSON of `shfmt --to-json`:

* `functions`: name, start and end lines;
* `blocks`: control structures and depth (else/elif at the same level);
* `commands`: literal name, literal arguments (`null` if expansion),
  `hasExpansion`, `checked` (if/while condition, left operand of `&&`
  / `||` — operators 10 and 11 —, negated command), `inLoop`,
  `inSubstitution`.

With the tree, command rules (SEC003, SEC012, ROB005, ROB007,
ROB011, POR004, POR005, POR007, PERF003, PERF004) and structural rules (MNT002,
MNT003) are exact; the `LineRule`s marked `astCovered` are then
ignored. Without shfmt, `lexScript` (comments, strings masked in
`bare`, heredocs) and regular expressions take over.

=== Adding a rule

. Add a `RuleInfo` to `ruleCatalog` (fr/en title and hint,
  contexts if any).
. Add its detection: a `LineRule` in `lineRules` (with
  `equivalents`, and `astCovered` + a case in `_astStructure` if it concerns
  a command), or a file rule in `runBuiltinRules`.
. If it must be raised in a context, complete
  `contextEscalations`.
. Tests: a triggering case and a clean case (`builtin_rules_test.dart` or
  `new_rules_test.dart`), then `UPDATE_GOLDEN=1 dart test test/corpus_test.dart`
  if the corpus changes — checking every difference.
. Update the rules table in `doc/user.adoc`.

== Directives, contexts, profiles

* `Suppressions.parse` reads `# check-script disable=` (line, or next code line
  for a standalone comment), `disable-next-line=`, `disable-file=`;
  wildcards `*` and `all`.
* `ExecContext` (`root`, `cron`, `systemd`): conditional rules
  (`RuleInfo.contexts`) and `contextEscalations` (severity only raised).
* `Profile`: `CheckConfig.forProfile` provides the base; `CheckConfig.parse`
  applies the YAML on top (the command-line profile takes precedence over the
  `profile:` key).

== Scoring and calibration

----
factor(n)   = √(reference / max(reference, lines of code))        reference = 100
penalty     = Σ_rules weight(severity) × (1 + log2 occurrences) × (factor if Medium/Low)
score       = clamp(10 − penalty, 0, 10), rounded to the tenth
global      = min(weighted average, worst category + 1.5)         maxGapToWorst
grade       = A ≥ 9, B ≥ 7.5, C ≥ 6, D ≥ 4, E
----

The `test/corpus/` *corpus* gathers frozen copies of scripts from the
AuditTools suite and typical scripts (`curl | bash` installer, old
cron backup, POSIX init script with bashisms, clean library), and
12 `py_*` Python scripts written for calibration (clean tool, sloppy API
client, dangerous installer, Python 2 style, 3.10+ features…). Semgrep is left
out of the grade checks (downloaded rules). `labels.yaml` gives for each
script, *established a priori by reading the script*, the expected range of
grades (with and without context), the mandatory and forbidden rules.

[source,bash]
----
dart run tool/calibrate.dart --details     # actual scores vs expected ranges
----

Two adjustments came out of it: dash-breaking bashisms classified High, and
the global score cap lowered from "worst + 2.5" to "worst + 1.5". Any
weight change must leave the corpus compliant.

The Python calibration (0.7.0) aligned severities with the shell scale without
touching the model: hardcoded secrets Critical if the value is realistic (like
SEC002), code or data execution High (like SEC003), PYSEC001
Medium (like SEC022), `python` shebang High; it added PYROB003 (cron
without lock, like ROB014) and PYROB004 (lost `main()` return code),
and counts docstrings as documentation. Three *a priori* ranges
judged too severe with respect to the shell scale were revised, with their
justification in `labels.yaml`.

== Automatic fixing

`fixScript` chains: ShellCheck replacements (`parseShellcheckFixes`,
`applyEdits`: 1-based positions, exclusive end, tab = 1 column,
conflicting edits ignored), built-in fixes (`applyBuiltinFixes`,
never inside a heredoc, a multi-line string or a comment;
`replaceBackticks` ignores apostrophes and escaped backticks), then
`shfmt -ln -i` on standard input. If `<shell> -n` accepts the original but
rejects the result, `FixResult.aborted` is set and nothing is written.
For a Python script (`_fixPython`): `ruff check --fix` then `ruff format`
on standard input (`--stdin-filename=script.py`), fixes being
counted from the JSON output; checked by Python compilation
(`syntaxRegression` uses `SyntaxAnalyzer.commandFor`).
`unifiedDiff` (Myers) produces the diff of `--dry-run` and of the interface.

== Baseline

`fingerprintAll` computes `fnv1a64(tool|rule|normalized line|rank)`: the
line number is not part of the fingerprint. `Baseline.parse` reads back a JSON
report; `compare` matches by fingerprint (multiset) and returns
`Comparison` (new, fixed, unchanged, previous scores). Reports
then detail only the new findings (`detailFindings`).

== Reports

`render(reports, format, RenderOptions)`; `OutputFormat`: `terminal`,
`markdown`, `asciidoc`, `json`, `sarif`, `html`, `codeclimate` (deduced from
the extension by `OutputFormat.fromPath`).

* SARIF: one rule per tool/rule pair (`help`, `helpUri`,
  `security-severity` for security), results with
  `partialFingerprints`, `startLine ≥ 1`.
* Code Quality: `check_name`, `severity` (blocker/critical/major/minor),
  `fingerprint`, `location.lines.begin`.
* HTML: single page without external resources, light/dark theme, filters,
  annotated source (anchors `#s<i>-L<n>`).

Types: `feat`, `fix`, `perf`, `refactor`, `docs`, `test`, `build`, `ci`,
`style`, `chore`, `revert`. Usual scopes: `engine`, `cli`, `gui`,
`python`, `rules`, `reporters`, `flatpak`, `appimage`, `rpm`, `ci`, `doc`.

* *Local check*: `scripts/install-git-hooks.sh` enables `.githooks/`
  (`core.hooksPath`); the `commit-msg` hook rejects a non-conforming message
  (`git commit --no-verify` to bypass it).
* *CI check*: `.github/workflows/commits.yml` checks the new
  commits of each push and pull request (`tool/commit_lint.dart --range`).
* *Release*: `dart run tool/release.dart --dry-run` displays the next
  version and the CHANGELOG section; without `--dry-run`, it synchronizes the
  version files, writes the CHANGELOG, commits `chore(release): X.Y.Z`
  and tags `vX.Y.Z` (`--push` to push, which triggers the GitHub
  release). Version: `feat` → minor, other change → patch,
  incompatible → major (minor while the version is 0.x). Notes
  written under "## Unreleased" are kept at the top of the section.

== Build and packaging

`scripts/build-dist.sh [VERSION] [--rpm] [--install] [--skip-tests] [--no-gui]`
(also called by the `AuditTools/scripts/build-dist.sh` orchestrator):
analysis and tests (Dart and Flutter), CLI binary, Flutter bundle (version
injected by `--build-name`), man page (asciidoctor), completions,
documentation and CI examples, `.desktop` and icon, SBOM and CVE report if
`sbom-generator` is present, archive, RPM (`scripts/build-rpm.sh`, from
`git archive HEAD`: only committed content is packaged).

`scripts/build-appimage.sh [--skip-build]`: Flutter bundle and compiled
CLI in an AppDir (`AppRun`: interface by default, CLI with `--cli`
or through a link named `check-script`), shared `.desktop`, icon and AppStream
metadata (`packaging/linux/`), then `appimagetool` (PATH,
`APPIMAGETOOL`, or downloaded into `build/appimage/`) → `dist/CheckScript-VERSION-ARCH.AppImage`.

`scripts/build-flatpak.sh [--install] [--skip-build]`: same binaries,
manifest `packaging/flatpak/fr.chla28.check_script_gui.yml` (GNOME 50
runtime, which provides GTK 3), `flatpak-builder` (or `org.flatpak.Builder`),
runtime and SDK installed from Flathub for the user →
`dist/CheckScript-VERSION-ARCH.flatpak`. Inside the Flatpak,
`ProcessCommandRunner` runs the tools on the host (`hostInvocation`:
`flatpak-spawn --host --env=LC_ALL=C …`, presence checked with `command -v`
on the host); the launchers put `TMPDIR` in the application cache,
whose path is identical in the sandbox and on the host.

Inside the Flatpak, the user's PATH on the host is read once by
a login shell (`bash -lc`, for `~/.local/bin`, `~/bin`…) and each
tool is launched by its *absolute path* resolved on the host: the portal
looks for the executable with its own minimal PATH, not the one from `--env`.

*Release* (`.github/workflows/release.yml`): on each `v*` tag, tests
(without external tools, for results independent of the tool versions
shipped by distributions), then archive, AppImage and Flatpak (Ubuntu 24.04), RPM
(Fedora 44 container), and GitHub release with the files and the CHANGELOG
excerpt. Flutter is pinned (`FLUTTER_VERSION`).

Both scripts share `scripts/package-common.sh` and display the minimum
glibc required by the binaries (currently 2.34: Rocky 9, Flatpak
runtimes); for a widely compatible AppImage, build on the oldest
targeted distribution.

The specs neutralize strip and debuginfo (they corrupt Dart AOT
binaries); the interface spec disables automatic dependency
scanning (embedded Flutter engine). License: LGPL-3.0-or-later
(`LICENSE`), reused by the specs and the AppStream metadata.

The version appears in `pubspec.yaml`, `gui/pubspec.yaml`,
`lib/src/version.dart` and `CHANGELOG.md`; `build-dist.sh` reports a
mismatch between the first two Dart files.
